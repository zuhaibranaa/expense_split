# EquiSplit — Mobile & Web Client

A cross-platform **expense splitting and group finance** app built with Flutter. Split bills, track who owes whom, and settle up on Android, iOS, Web, macOS and Windows from a single codebase.

EquiSplit is **serverless**: the app talks directly to Firebase (Auth, Firestore, Storage, Cloud Functions, FCM). There is no REST API and no Laravel backend in the request path. The retired Laravel implementation lives in the sibling [`equisplit`](https://github.com/zuhaibranaa/equisplit) repository for historical reference only.

---

## ✨ Features

### Groups & people
- Create groups for trips, roommates, events or households
- Invite members with a shareable `/join?token=` link and claim it on a second account
- Member directory with avatars, contact details and per-group roles
- Cash-inflow tracking — money coming *in* (salary, refunds) linked to specific expenses

### Expenses & splitting
- Add expenses with amount, category, date and payer
- Split across any subset of members — equally or by custom shares
- Automatic balance calculation: who owes whom, minimised into a settlement list
- Settlement tracking, so a recorded payment clears the debt

### Analytics
- Spending statistics and trends per group, rendered with FL Chart
- Category breakdowns and cash-flow charts

### Platform & real-time
- **Live updates** from Firestore snapshots — balances and expenses appear without a refresh
- **Push notifications** via FCM, including settlement reminders and expense alerts
- **Offline-first** — Firestore caches reads and queues writes until connectivity returns
- Google sign-in, email/password auth, avatar uploads to Firebase Storage
- Slidable expense rows, emoji picker, currency picker, in-app ads on mobile

## 🏗️ Architecture

Feature-first structure with a shared layer:

```
lib/
├── main.dart                       # Entry point (Firebase bootstrap, sign-in init, ads)
├── firebase_options.dart           # Generated by flutterfire configure
└── src/
    ├── app.dart                    # App shell & theme
    ├── core/
    │   ├── constants/              # Default category list
    │   └── firebase/
    │       ├── firebase_bootstrap.dart   # init + emulators + App Check
    │       ├── firestore_refs.dart       # typed collection/document refs
    │       ├── firestore_converters.dart # Timestamp/num/string converters
    │       └── firebase_error_mapper.dart
    ├── features/
    │   ├── auth/                   # Firebase Auth, profile, invites, avatar
    │   ├── home/                   # Dashboard & personal balance
    │   ├── groups/                 # Group list, detail, invites
    │   ├── expenses/               # Expenses, splits, settlement, balances
    │   ├── categories/             # Category management
    │   ├── cash_inflows/           # Income / cash-inflow tracking
    │   ├── people/                 # Member directory
    │   └── analytics/              # Statistics & charts
    └── shared/
        ├── services/               # FCM/local notifications
        ├── presentation/widgets/   # Reusable UI widgets
        └── utils/                  # Formatters, platform detection, helpers

functions/                          # Cloud Functions (TypeScript, Node 20)
├── src/auth.ts                     # bootstrapUser, syncMemberProfile
├── src/groups.ts                   # invites, members, delete, reset
├── src/expenses.ts                 # onExpenseCreated push
├── src/notifications.ts            # reminders, test push
├── src/devices.ts                  # hasFcmToken mirrors
├── src/cleanup.ts                  # scheduled invites + onUserDelete
└── src/lib/                        # Admin SDK helpers, FCM, constants

firestore.rules                     # Security rules
firestore.indexes.json              # Composite + collection-group indexes
storage.rules                       # Avatar-only bucket rules
firebase.json                       # Rules/indexes/storage/functions/emulators
```

**State management:** [Riverpod](https://riverpod.dev). Repositories expose `Stream`s over Firestore, and providers are scoped per feature.

**Balance math:** `BalanceCalculator` is pure Dart and runs in the client (`features/expenses/domain`). There is no `users.balance` field; the personal balance is derived as `cash inflows − personal-group expenses`.

**Routing:** `Navigator` + `MaterialApp.home`; invite links are read from `Uri.base.queryParameters['token']` in `AuthGate`.

## 🛠️ Getting started

### Prerequisites

- **Flutter SDK** 3.47 or higher
- **Dart** 3.13 or higher
- **Node.js 20** and `firebase-tools` (`npm i -g firebase-tools`) for Functions and emulators
- **JDK 21+** — `firebase-tools` refuses to start the emulators on older runtimes
- Platform toolchains: Xcode + CocoaPods (macOS/iOS), Android Studio/SDK, Visual Studio 2022 (Windows)

The Firebase project is **`equisplit-d4c74`**. Its client config is already committed in `lib/firebase_options.dart`, `android/app/google-services.json`, and the Apple plists.

### 1. Clone & install

```bash
git clone https://github.com/zuhaibranaa/expense_split.git
cd expense_split

flutter pub get
npm --prefix functions install
```

### 2. Run against the Firebase emulators

Start the emulator suite (Auth, Firestore, Storage, Functions, UI):

```bash
firebase emulators:start
```

Then launch the app with the emulator flag:

```bash
flutter run -d chrome --dart-define=USE_FIREBASE_EMULATORS=true
```

The Android emulator automatically uses `10.0.2.2` for the host; every other target uses `localhost`.

### 3. Run against the real project

```bash
flutter devices

flutter run -d chrome
flutter run -d macos
flutter run -d windows
flutter run -d <android-or-ios-device>
```

### 4. Deploy rules, indexes and functions

```bash
firebase deploy --only firestore:rules,firestore:indexes,storage
npm --prefix functions run build
firebase deploy --only functions
```

Functions deploy to `europe-west1` (see `functions/src/index.ts`). Set the invite link host if you use a custom domain:

```bash
firebase functions:config:set  # legacy; for v2 params use functions/.env
# functions/.env
INVITE_BASE_URL=https://app.example.com
```

Without `functions/.env`, invite links default to `https://equisplit-d4c74.web.app`.

### Optional: App Check

Client wiring is compiled out unless you pass:

```bash
flutter run -d chrome --dart-define=ENABLE_APP_CHECK=true
```

Do not enforce App Check in Firebase until parity QA passes.

## 🧪 Quality

```bash
flutter analyze                    # static analysis
flutter test                       # 33 unit tests (converters, models, balances, errors)
dart format lib test
npm --prefix functions run build   # type-check Cloud Functions
npm --prefix functions run lint
```

Rules and end-to-end tests run on the Firebase emulators (JDK 21+ required):

```bash
# Firestore + Storage rules (36 tests, every deny path)
firebase emulators:exec --only firestore,storage \
  "npm --prefix functions test"

# Golden path: signup → personal group → invite → claim → expense → reminders
#              → reset → remove member → delete group
firebase emulators:exec --only auth,firestore,functions \
  "npm --prefix functions run test:integration"
```

The golden-path test talks to the emulator REST APIs directly, so the real rules and callables are exercised without the Flutter client.

## 🔍 Troubleshooting

**Web**
- `auth/unauthorized-domain` → add the origin under Firebase Auth → Settings → Authorized domains
- Push does nothing → confirm `web/firebase-messaging-sw.js` is served from the site root and the VAPID key matches `NotificationService._vapidKey`

**macOS / iOS**
- CocoaPods errors → `pod install` inside the platform directory
- Google sign-in fails → check the `REVERSED_CLIENT_ID` URL scheme is in `Info.plist`

**Android**
- Emulator can't reach emulators → `10.0.2.2` is handled automatically by `firebase_bootstrap.dart`; verify the emulator is started with `firebase emulators:start`
- `google-services.json` missing → re-run `flutterfire configure --project=equisplit-d4c74`

**Functions**
- `permission-denied` calling a function → send a CORS-enabled call from the app (callables do this) and check the user is signed in
- `internal` errors → `firebase functions:log`

**General**
- Build errors → `flutter clean && flutter pub get`
- Platform unavailable → `flutter doctor`
